# 가게 색인(storeidx) 파이프라인

> beta.61(2026-11-22)부터. 가게 찾기(음식점 앱 처음 설정 1/3·설정의 가게 찾기 창, 담당자 웹 '이름으로 검색', 직원 앱 음식점 등록)가
> 공공데이터 API에 매번 묻지 않고, **주 1회 만든 정적 색인**에서 바로 찾게 하는 자료다. 형식은 계약이다 — [04-contracts.md](handover/04-contracts.md) C17.
> 기관·부서 자료는 별도: [agency-data-pipeline.md](agency-data-pipeline.md).

## 1. 왜

- 공공데이터(data.go.kr) 일반음식점 API는 느린 날 한 건에 5.7~41초가 걸리고(2026-11-14 실측), 한글 조건이 0건이 되는 장애도 있었다(2026-08).
  가게 찾기가 그날 공공데이터 상태에 좌우됐다.
- 색인은 시군구별 정적 JSON이라 GitHub Pages가 그대로 서빙한다. 서버(Workers 무료 플랜)·공공데이터 API 쿼터를 쓰지 않는다.
- 가게 **등록**의 실존 대조(서버가 관리번호로 공공데이터에 묻는 것)는 그대로다. 색인은 고르기만 돕는다.

## 2. 출처와 받는 법

| 항목 | 값 |
|---|---|
| 원자료 | 행정안전부 지방행정 인허가데이터 — 일반음식점 전체 파일 |
| 주소(전국) | `https://file.localdata.go.kr/file/download/general_restaurants/info` (약 700MB) |
| 주소(시군구 하나) | 위 주소 + `?orgCode=<개방자치단체코드>` (예: `3040000` = 광진구 — 견본·시험용) |
| 받기 전 확인 | `GET https://file.localdata.go.kr/file/validate/download-count` — `429`면 내려받기 한도 |
| 필요한 머리 | 브라우저 `User-Agent`와 `Referer: https://file.localdata.go.kr/file/general_restaurants/info` (없으면 `403`) |
| 형식 | CSV, **cp949**, 39열, 첫 줄이 머리 |
| 쓰는 열 | `관리번호`·`영업상태코드`(`01`=영업)·`사업장명`·`도로명주소`·`지번주소`·`도로명우편번호` |

로그인·키는 필요 없다(공개 자료). 비밀값을 쓰지 않는다.

## 3. 형식 v1

```
storeidx/meta.json
  { "v":1, "built":"YYYY-MM-DD", "total":<영업 가게 수>,
    "regions": { "<시도 전체 이름>": { "<시군구 키>": { "f":"<slug>/<번호>.json", "n":<건수> } } } }

storeidx/<시도 slug>/<번호>.json
  { "v":1, "rows":[ [관리번호, 사업장명, 도로명주소, 지번주소, 도로명우편번호], … ] }
```

- **영업 중(`01`)만** 넣는다. 사업장명 가나다순. 파일 이름은 ASCII.
- **시도 이름·시군구 키는 `zipmap/`과 같은 표기**다(`harness/build-zipmap.mjs`·`zipmap/index.json`). 앱의 지역 해석기가 그 키를 그대로 쓴다.
  세종처럼 시군구가 없는 곳도 zipmap과 같게(키 = 시도 이름). `<번호>`는 `zipmap/index.json`의 그 시도 시군구 목록 순번(2자리)이라
  zipmap이 그대로면 날마다 같은 파일 이름이 된다.
- 가게의 지역은 `개방자치단체코드`가 아니라 **주소(도로명주소, 없으면 지번주소)의 앞머리**로 정한다. 앞머리가 zipmap에 없으면
  (이름이 바뀐 구, 일반구가 빠진 주소 등) 우편번호 → 동 이름 순으로 zipmap에서 찾는다.
- **전화번호는 넣지 않는다**(불변식 4 — 사업장 전화는 저장 없이 중계만). 그래서 색인으로 고른 가게는 앱에서 전화번호 칸이 비어 있다.
- 버리는 행: 열 수가 다른 행, 관리번호 없음·중복, 사업장명 없음, 주소 둘 다 없음, 지역을 정할 수 없음. 수를 집계(`--report`)에 남긴다.
  한 파일이 3MB를 넘으면 로그에 경고한다.
- 형식을 바꿀 때는 `v`를 올리고, 읽는 쪽 셋(음식점 앱·담당자 웹·직원 앱)을 먼저 배포한다. 읽는 쪽은 `v`가 1이 아니면 색인을 쓰지 않는다.

## 4. 만드는 명령

```bash
node harness/build-storeidx.mjs <전국 CSV 경로> [--out 폴더] [--min-total N] [--report 파일]
node harness/build-storeidx.mjs --download [--keep <내려받을 파일>] [--org-code 3040000] [--min-total N] [--report 파일]
node harness/build-storeidx.mjs --mirror https://app.bapjangbu.com/storeidx/ [--out 폴더]   # 라이브 색인을 그대로 받아 오기
node harness/storeidx.test.mjs     # 견본 cp949 CSV로 만든 결과 검사(네트워크 없음, CI 게이트)
```

- 출력 기본값은 리포의 `storeidx/`이고 **`.gitignore`에 들어 있다 — 리포에 커밋하지 않는다.**
- 끝까지 성공해야 출력 폴더를 바꿔 끼운다(임시 폴더에 다 쓴 뒤 교체). 실패하면 예전 폴더가 그대로 남는다.
- `--min-total N`: 영업 가게가 N보다 적으면 실패(잘린 파일·형식 변경을 배포하지 않게). CI는 `500000`.
- `--built`: `meta.built` 값(기본 한국 시각 오늘).
- 외부 패키지 없음. cp949 확장 한글(똠·햏 등)은 Node 내장 해석기가 빌드에 따라 못 풀어서, 생성기가 표를 직접 만든다(자기 점검 포함).
- 견본: `harness/fixtures/storeidx-sample.cp949.csv` — 광진구 공개 자료의 일부 행과 경계 사례 합성 행(`make-storeidx-sample.py`로 만듦, 전화번호는 표식 값으로 바꿈).

## 5. 워크플로(`.github/workflows/pages.yml`)

색인은 **GitHub Pages 아티팩트에만** 실린다. 앱 배포는 색인 때문에 실패하지 않는다 — 색인 단계는 전부 `continue-on-error`.

| 실행 | 동작 |
|---|---|
| `push`(main) | 지금 라이브 색인을 그대로 가져와 싣는다(`--mirror`). 라이브에 없을 때만 새로 만든다. 하루에 여러 번 push해도 700MB를 매번 받지 않게 |
| 예약(주 1회 — UTC 일요일 18:23 = 한국 월요일 03:23) | 공공데이터 전국 파일을 받아 새로 만든다(`--download --min-total 500000`). 실패하면 라이브 색인을 그대로 가져온다 |
| 수동(`workflow_dispatch`) | 예약과 같다. 입력 `storeidx_only`를 켜면 **배포 없이** 색인 만들기만 시험하고 `meta.json`·집계를 이 실행의 아티팩트(7일)로 남긴다 |

- 마지막 점검 단계가 `storeidx/meta.json`이 없으면(만들기·가져오기 모두 실패) 폴더를 빼고 **색인 없이 배포**한다 — 읽는 쪽은 예전 방식으로 찾는다.
  어느 경우였는지는 실행 요약(`### 가게 색인: …`)에 남는다.
- 예약 실행도 `test`·`smoke` 게이트를 그대로 거친다.

## 6. 실패하면 어떻게 되나

| 상황 | 결과 |
|---|---|
| 공공데이터 내려받기 실패(429·403·시간 초과)·자료가 잘림 | 라이브 색인 그대로(어제 것). 기준일(`built`)이 하루 밀린다 |
| 라이브 색인도 못 가져옴 | 색인 없이 배포. 앱·담당자 웹·직원 앱은 예전 방식(서버 이름 검색 → 동네 순회) |
| 사용자 기기가 색인을 못 받음(오프라인·404·형식 다름) | 그 기기에서만 예전 방식 |
| 색인에서 0건 | 예전 방식으로 저절로 넘어가지 않는다. "『○○구』에서 '△△' 이름의 영업 중인 가게를 찾지 못했어요…" + "YYYY-MM-DD 기준 공공데이터" + [공공데이터에서 다시 찾기] |
| 예약 실행이 멈춤(공개 리포는 **60일 동안 커밋이 없으면** GitHub가 예약 실행을 끈다) | 라이브 색인이 마지막 것 그대로 남는다(기준일이 멈춤). Actions 탭에서 워크플로를 다시 켠다 |

## 7. 읽는 쪽

| 서피스 | 지역을 정하는 법 | 받는 주소 |
|---|---|---|
| 음식점 앱 | 지역 칸(구·군과 동)에서 시도·시군구가 정해질 때 | 같은 출처 `storeidx/…` |
| 담당자 웹 | 2단계에서 고른 기관의 관할(시도·시군구) | `https://app.bapjangbu.com/storeidx/…` (CSP `connect-src`에 등재) |
| 직원 앱 | 관리 탭의 이용 지역(시도·시군구) | `https://app.bapjangbu.com/storeidx/…` |

- 이름은 정규화 부분 일치(띄어쓰기·괄호 무시 — 서버 `normalizeStoreName`과 같은 규칙). 동을 적었으면 주소에 그 동이 든 가게를 앞에 둔다.
- 시도는 추측하지 않는다(동명 구: 중구·서구 등). 키가 안 맞으면 색인을 쓰지 않는다.
- 색인 파일은 서비스워커 프리캐시에 넣지 않고, 받은 구 파일은 그 실행 동안 메모리에만 둔다.

## 8. 아직 확인하지 못한 것

- GitHub 러너(해외 IP)에서 `file.localdata.go.kr` 내려받기가 되는지 — 푸시 뒤 `workflow_dispatch`(`storeidx_only`)로 먼저 시험한다.
  막히면 예약 실행은 매번 라이브 색인을 그대로 가져오게 되므로, 그때는 다른 곳에서 만들어 올리는 방법을 정한다([09](handover/09-open-items.md) C16).
