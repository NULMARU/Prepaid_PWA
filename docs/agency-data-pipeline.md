# 기관·부서 데이터 파이프라인

전국 광역·기초 자치단체와 각 본청의 '과' 목록을 담은 `agency-index.json` /
`agency-depts/{region}.json` 를 생성·갱신하는 절차를 정리한다.
가게 찾기용 음식점 색인(`storeidx/`)은 따로 — [storeidx-pipeline.md](storeidx-pipeline.md).

## 출처

- **행정안전부 행정표준코드 관리시스템**(code.go.kr) — "기관코드" 전체자료.
  헤더 1행 + 약 47.3만 행(폐지 조직 포함, 존속 약 13.3만). **현재 산출물 = 2026-11-20 제공분**(zip 안 파일 날짜 2026-11-20,
  최종 변경일자 최댓값 2026-11-19, 2026-11-22에 받음). 이전 스냅샷은 2026-07.

## 원자료 받는 법 (2026-11-22 확인 — 로그인·인증 없음)

1. code.go.kr → 상단 [기관코드] 화면(`/stdcode/orgCodeL.do`) → 목록 위 **[기관코드 전체자료]** 버튼.
   (같은 줄의 [기관코드 조회자료]는 2만 건 이하 검색 결과용이라 쓰지 않는다.)
2. 버튼은 `POST /etc/codeFullDown.do`(폼 값 `codeseId=기관코드`)를 보내고 `기관코드 전체자료.zip`(약 18MB)을 준다.
   한 번 받은 뒤 15초 안에 다시 누르면 "다운로드 중" 안내가 뜬다.
3. zip 안에는 두 파일이 있다. 스크립트 열 번호는 **`기관코드 전체자료(유형분류 의미추가).txt`(27열)** 기준이다
   (`기관코드 전체자료.txt`는 의미 열이 빠진 24열 — 넣으면 열이 어긋난다).
4. **파일은 CP949·CRLF**다(예전 기록의 "UTF-8 TSV"는 변환한 사본이었다). 압축 안 파일명도 CP949라 macOS `unzip`은 실패한다 —
   `python3 -I`의 `zipfile`로 풀고 `decode('cp949')` 후 UTF-8로 저장해 넘긴다. 원자료는 리포에 넣지 않는다.

## 재생성 절차 (연 1회 + 광진구처럼 거래 기관 개편 소식이 있을 때)

```bash
# 1) 위 방법으로 받아 UTF-8로 바꾼 원자료를 리포 밖에 둔다
# 2) 먼저 리포 밖 사본에서 돌려 차이를 본다(outDir에 agency-departments.json 사본을 함께 둘 것)
node harness/build-agencies.mjs <org_utf8.txt> <스크래치 폴더>
# 3) 차이를 확인한 뒤 리포에서
node harness/build-agencies.mjs <org_utf8.txt>
# → agency-index.json, agency-depts/*.json (17개) 재생성
```

재생성 전에 스크립트의 `UPDATED_AT`·`SOURCE`·`AS_OF`(원자료 제공일)를 새 자료에 맞게 고친다.

스크립트(`harness/build-agencies.mjs`)가 곧 파이프라인 전체다. Node 표준
라이브러리만 사용한다.

## 필터 규칙 (원자료에서 직접 검증해 확정)

- **존속만**: `존폐여부` 열 == `0`. (폐지행은 `1`이며 전부 `폐지일자` 보유 —
  존속행은 폐지일자가 NULL 또는 공란. 46.9만 행 중 존속 약 13.2만.)
- **기준일 뒤에 생길 조직은 뺀다**(2026-11-22 추가, 스크립트 `AS_OF`): 원자료에는 개편 예정 조직이 미리 등록된다 —
  `생성일자`가 미래이고 `존폐여부`는 0이다. 2026-11-20 자료에서는 **성북구(2026-12-28 시행)**·**양평군(2027-01-01 시행)** 개편분이 그렇다.
  이 행을 넣으면 아직 없는 과와 지금 있는 과가 한 목록에 섞여, 같은 일을 하는 과가 두 이름으로 보인다(예: 성북구
  '어르신·장애인복지과'와 새 '어르신˙장애인복지과'). 그 개편이 시행된 뒤 원자료를 다시 받아 재생성한다.
  (용산구는 2027-01-01 개편분을 등록했다가 2026-11-11에 취소해 폐지행으로 남아 있다 — 영향 없음.)
- **본청(자치단체)**: `유형분류_대` == `02`(자치행정조직) & `기관코드`==`대표기관코드`
  & `유형분류_중` ∈ {`01` 광역, `02` 기초}.
- **본청 '과'**: `유형분류_대`==`02` & 최하위기관명이 '과'로 끝남 &
  `유형분류_중` ∈ {`01`,`02`,`09`}(광역 자체·기초 자체·보조기관).
  분류체계가 지자체마다 불균일해서(같은 과라도 어떤 곳은 보조기관 09·소05,
  다수 군은 기초 자체 02·소03, 일부 도청은 광역 01로 태깅) 소(小)코드 단일
  기준은 신뢰할 수 없다. 상위 경로에 **읍·면·행정동** 또는
  **소방·보건소·사업소·공단·상수도·농업기술·연구원·의회·직속기관·출장소** 표지가
  있으면 본청 밖 조직으로 보고 제외한다(팀·계·읍면동·보건소·사업소·직속기관·
  의회사무국 제외 원칙).
- **제주 행정시(제주시·서귀포시)**: 하부행정기구라 국 소속 과가 중09·소05로,
  일부는 중03·소06으로 분류되어 특례 처리한다.

> awk 등 로케일 의존 도구에서 한글 문자열 비교가 오작동(예: "동"=="과"가 참)하는
> 환경이 있어, 모든 한글 필터링은 Node(JS)에서 수행한다.

### 2026-11-22 현행화 (행정표준코드 2026-11-20 제공분 대조)

큐레이션을 원자료와 대조해 **원자료 근거가 있는 차이만** 고쳤다. 규칙:

- 원자료에 **존속하는 과**(위 필터 규칙 + 기준일)는 넣는다. 구청 경로에 '보건소'가 있는 과는 `○○구보건소`로.
  서울시청은 본청 밖인 도시기반시설본부·서울대공원·시민안전체험관·어린이병원의 과를 뺀다.
- 큐레이션에 있던 과가 원자료에 **폐지행으로만** 있으면 뺀다.
- 원자료와 글자만 다른 과(가운뎃점)는 원자료 표기로 바꾼다: 성북 '어르신장애인복지과'→'어르신·장애인복지과',
  강북 '어르신장애인과'→'어르신·장애인과'. 서초 '의료지원과'는 원자료상 보건소 과라 서초구보건소로 옮겼다.
- 큐레이션에 있지만 원자료에 **한 번도 없던 이름**(존속·폐지 모두 없음)은 근거가 없어 **그대로 두고** 목록 끝에 남겼다
  (서울시청 7·구청 25·보건소 3 — 예: 서울시청 '예산과', 중랑구 '안전재난과', 노원구 '도로과'). 다음 확인 때 누리집으로 가릴 것.
- 순서: 기존 과는 큐레이션 순서를 지키고 새 과를 뒤에 붙였다. **광진구청·광진구보건소는 구청 누리집 조직도 순서 그대로.**

결과: 서울시청 66→132(+78 · −12), 25개 구청 합계 +287 · −118, 25개 보건소 합계 +46 · −16(이 중 2026-06-16 이후 실제 개편은 광진·마포·동작과 서울시청 일부,
나머지는 6월 큐레이션이 빠뜨렸거나 이미 폐지된 이름을 담고 있던 것).

## 보건소 분리 규칙 (2026-11-07)

현장 사고에서 확정한 기준이다. 사장님 앱(부서 목록 고르기)과 담당자 웹(기관 고르기)이 **같은 목록**을 쓰므로,
목록에 보건소가 없으면 사장님은 `광진구청 + 보건의료과`, 서무는 `광진구보건소`로 갈라져 같은 직원이 두 부서에 생긴다.

- **보건소는 별도 기관**이다. 광역청을 뺀 모든 기초자치단체(제주 행정시 포함) 바로 뒤에 `{시군구}보건소`
  (id `${id}-health`, `district` = 시군구명)를 둔다. `district`는 담당자 웹이 관할 음식점을 조회할 때 쓴다
  (이름이 `…청`이 아니라서 이름에서 시군구를 뽑을 수 없다).
- 시 하나에 보건소가 여럿(일반구)이어도 항목은 하나다. 목적은 "양쪽이 같은 이름을 고르게" 하는 것이지 공식 명칭 사전이 아니다.
- **서울 큐레이션**(`agency-departments.json`)은 구청 과 목록에서 `보건·건강·의약·감염·진료`가 든 과를 보건소로 옮긴다.
  서울시청의 건강정책과·감염병관리과는 본청(시민건강국)이라 그대로 둔다.
  (2026-11-22 대조: 시민건강국의 원자료 과는 감염병관리과·건강관리과·공공의료과·보건의료정책과·스마트건강과·식품정책과·정신건강과이고,
  '건강정책과'는 원자료에 없는 이름이라 "미확인"으로 남아 있다.)
- **자동 추출 지역의 보건소 과 목록은 비워 둔다.** 원자료의 보건소 과(중05 직속기관 하위)는 추출하지 않는다.
  비어 있으면 앱은 "불러온 과 목록이 없어요 — 직접 추가" 안내를 띄우고, 담당자 웹의 부서는 자유 입력이라 영향이 없다.
- 세종은 광역만 있어 보건소를 등재하지 않는다(세종특별자치시청 + 부서명으로 쓴다).
- 2026-11-07 적용분은 원자료 재실행이 아니라 기존 산출물에 위 규칙을 한 번 적용한 것이다(기관 246 → 475).
  스크립트(`build-agencies.mjs`)에도 같은 규칙이 들어 있어 다음 재생성 때 그대로 유지된다.

## 품질 한계

- 광역시·특례시(예: 경기도청·부산광역시청)는 본부·북부청사·일반구 등 같은
  자치단체 내 다수 조직의 과가 함께 잡혀 목록이 길 수 있다(누락보다 과다 포함).
- '과' 명칭·중분류 태깅이 지자체마다 달라, 드물게 경계 사례가 포함/누락될 수 있다.
- 광주광역시청·전라남도청은 상기 통합 사유로 부서 목록이 비어 있다.
- 원자료 스냅샷 시점 이후의 조직 개편은 재실행 전까지 반영되지 않는다.
  **예정된 개편(2026-11-20 자료 기준)**: 성북구 2026-12-28, 양평군 2027-01-01 — 시행 뒤 다시 받아 재생성할 것.
- 원자료는 각 기관이 직접 입력한다. 개편 뒤 옛 과를 폐지 처리하지 않은 기관이 있으면 옛 이름이 함께 남는다
  (광진구는 누리집과 일치 확인, 나머지 구는 누리집 대조를 하지 않았다).
