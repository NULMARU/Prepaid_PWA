## 2. 참고 영상 핵심 및 적용한 한 줄

9월에 확인한 영상의 핵심은 필요한 이미지를 먼저 만들고 그 이미지와 페이지를 함께 디자인하라는 것입니다. 이미지를 장식으로 덧붙이는 것만으로는 충분하지 않습니다. 이번에는 기존 홍보 사진 대신 작은 브랜드 캐릭터와 실제 앱 화면을 사용했습니다.

적용 방향: **“손님은 적고, 사장님은 확인한다 — 첫 화면은 시작에 필요한 만큼만.”**

## 3. 시각 언어·내용

종이색·잉크 남색·시스템 고딕을 유지했습니다. 큰 반복 카드와 장문의 설명을 없애고 단순한 구획·텍스트 링크로 구분했습니다. 이미지 생성 프롬프트와 자산 위치는 브랜드 안내 문서에 있습니다.

390×844 기준 문서 높이 약 14,575px → 2,492px(약 83% 감소). 닫힌 FAQ 기준 약 3화면이며, 펼친 상태에서는 길어집니다. 세 역할 버튼은 360/390/768/1280 모두 첫 화면 안에 있습니다.

손님 이름 확인은 인증이 아니라 오선택 방지라는 점을 매뉴얼에 명시했습니다. 사장님 PIN 후 확인·저장이 필요하고, 사장님이 금액을 바꾸면 서명을 다시 받아야 합니다. 직원 개인 기록장은 음식점 장부와 자동 연결되지 않습니다.

## 5. 최초 개정본의 출력물·이메일·Claude 검토 (후속 개정 전 기록)

출력물: 음식점 사장님 25쪽, 기관 담당자 14쪽, 직원 10쪽, 손님용 A4 1쪽. 3종 안내서 첫 페이지에는 빠른 사용 순서를 별도로 배치했습니다. 기존 상세 설명은 보존했습니다.

HTML 원본을 PDF로 생성하고 PyMuPDF로 전체 50쪽을 렌더링·검사했습니다. 담당자·직원·손님 안내문은 Chrome 인쇄 엔진, 사장님 안내서는 마지막 인쇄 겹침 수정 후 WeasyPrint로 재생성했습니다. 빈 페이지·텍스트 페이지 밖 이탈 0, 한글 출력·페이지 구분 확인. 안내서 페이지 번호와 링크의 운영 주소 정규화도 적용했습니다. 손님 안내문은 큰 글씨·흑백 출력 가능 구성입니다. 실제 프린터 시험은 하지 않았습니다.

PDF 재생성: `harness/export-manual-pdfs.mjs`, 사장님 안내서의 브라우저 없는 재생성은 `harness/export-owner-pdf.py`. 최종본은 `docs/manuals/`와 `output/pdf/`에 동일하게 보관합니다.

### Claude 독립 검토 및 반영

3번째 Claude 터미널에서 읽기 전용 검토 완료. 최종 의견은 “핵심 흐름·개인정보 인증 설명·앱 실제 동작·메인 간결함·인쇄 적합성 모두 적합, A·B 정리 후 이메일 발송 가능”입니다.

- A 반영: `.gitignore`에 `/output/pdf/`만 추가해 이메일용 중복 사본을 제외했습니다. 배포용 PDF는 docs/manuals/에 유지합니다.
- B 반영: 도움말 푸터에 Cloudflare 암호화 명단 중계·암호화 클라우드 백업 및 개인정보처리방침 고지를 넣었습니다.
- 선택 의견도 반영: 도움말 파비콘 통일, 섹션 번호 01/02/03 정리, 상단 안내 링크 44px 이상, 사장님·직원 안내서의 잔액 설명 중복 제거.
- 기존 9월 사진 자산은 이력·재사용을 위해 삭제하지 않았으며 새 메인에서 불러오지 않습니다.
- Claude도 4폭 반응형·최소 글자 크기·대비·모의 의견 전송·기존 URL 8개·PDF A4와 1쪽 손님 안내·PDF 사본 동일성을 확인했습니다.
- 배포 영역이 서로 다른 점은 남겨 두었습니다. 이번 작업에서는 배포하지 않았습니다.

사용자가 이미 설명한 손님/사장님 역할은 다시 묻지 않았습니다. 추가 사용자 결정 없이 진행했습니다. 상표 등록 가능성, 실제 기기 인쇄 및 연령대별 사용성 시험은 이번 검증 범위가 아닙니다. 신규 URL은 아직 공개되어 있지 않습니다. 배포 시 홈페이지와 앱의 docs 문서를 함께 갱신해야 링크와 안내 내용이 맞습니다.
